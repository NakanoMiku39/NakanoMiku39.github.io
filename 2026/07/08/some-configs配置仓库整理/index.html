some_configs配置仓库整理

2026年07月08日

这篇文章整理一下我的 some_configs 配置仓库。仓库里的配置按 GNU Stow 的方式组织，每个顶层目录基本就是一个可以链接到 $HOME 的配置包。本文只说明仓库里各组件的职责、配置路径和基本安装方式，实际启用哪些组件取决于使用的系统、桌面会话和个人工作流；下面的分类不是安装顺序，也不是偏好排序。

AIGC：这篇文章由AI生成

同类组件不要重复启用

这个仓库不是一套“全部装上就完事”的配置，而是把不同桌面环境、不同启动器、不同通知组件和不同 shell 提示符都放在一起保存。同一功能的多个组件通常不在同一个会话里同时启用，否则可能出现重复进程、快捷键冲突或多个界面同时接管同一类功能。

功能 仓库中对应的软件
Wayland 窗口管理 niri
X11 窗口管理 i3wm
macOS 窗口管理 aerospace
状态栏 waybar、i3blocks、i3status、polybar
启动器 walker、fuzzel、rofi
通知 swaync、mako
锁屏 swaylock、i3lock 脚本
shell 提示符 powerlevel10k、starship
壁纸 swaybg 启动项、swaybg.service

Fedora/dnf 示例：

这份 Waybar 配置是顶部栏，模块包括：

  • 左侧：电源菜单和托盘。
  • 中间：时钟，时区是 Asia/Shanghai。
  • 右侧：通知数量、网络、蓝牙、音量、电池。

启动器

Walker 配置里启用了应用启动、计算器、网页搜索等 provider，并设置了一些前缀：

@ 网页搜索
$ 窗口切换
bt: 蓝牙设备

Mako

仓库里还保留了 Mako 配置：mako/.config/mako/config。

Fedora/dnf 示例：

Mako 配置里设置了右上角位置、圆角、边框、图标、历史数量、低优先级和严重通知的不同颜色。

swaync 和 mako 都是通知守护进程。同一个会话里同时启动二者会让通知行为变得不明确。如果从 SwayNC 切换到 Mako，需要把 Niri 自启动里的 swaync 改为 mako，并同步调整 Waybar 里调用 swaync-client 的通知模块。

i3status

它会显示无线网络、有线网络、电池、磁盘、内存和本地时间。i3blocks 和 i3status 都是 i3 状态栏方案，实际使用时选一个即可。

Rofi

Picom

Picom 配置在 picom/.config/picom/picom.conf。

picom 是 X11 合成器。Wayland/Niri 会话不使用 X11 合成器。
